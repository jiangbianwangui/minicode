# 留出任务：skill 到底迁移了什么

> 这是一次**自我更正**的记录。2026-11-07 我写下「B 组和 A 组总分完全一样，净效果为零」，
> 今天（11-19）用脚本重跑，那句话**没有复现**——B 组的检查点分数稳定高于 A 组。
> 但「B 组一次都没通过」这一点复现了。下面是完整数据和修正后的结论。

## 1. 为什么要留出任务

前 10 个有效任务的 skill **都是做完题才写的**——等于开卷考试。
所以「skill 有效」只说明「答案放在它能拿到的地方时，它抄得对」，
说明不了 skill 有没有**可迁移的知识价值**。

留出任务 = 一道**永远没有配套 skill** 的题。它能被解（有参考 skill 证明上限），
但那个 skill 从不进 `skills/`，路由扫不到。

## 2. 三组对照

| 组 | 给什么 | 测的是 |
| --- | --- | --- |
| A | 什么都不给 | 基线：模型自己的先验 |
| B | **现有 13 篇库** | 关键组：能不能把别处的规范迁移过来 |
| C | 专属 skill（`eval/heldout/`，跑完即移走） | 上限：这题确实可解 |

防污染：C 组必须把参考 skill 临时复制进 `skills/` 才能被召回。手动做这件事，
**忘了移回来会污染之后所有 base 运行**——t38 就因为读到刚写的 skill 被击穿过一次。
所以 `eval/run_heldout.py` 用 `try/finally` 复制与清理，结束时断言目录已空。

## 3. 两道题

| | t39 告警静默 | t40 临时提权 |
| --- | --- | --- |
| 业务 | 告警平台的静默申请 | 权限系统的提权申请 |
| 返回值 | apply / schedule / review / reject | grant / grant_staged / review / deny |
| 同构于库里的 | `backfill-approval-policy` | `export-approval-policy` |
| 骨架 | 短路直通 → 一票否决 → 超长降级 → 转人工 → 兜底 | 同左 |
| 关键参数 | 30 分钟 / 24 小时 | 4 小时 / 12 小时 |
| 实际召回到 | `backfill-approval-policy`（10.4 分） | `export-approval-policy`（10.1 分） |

两道题都是「五条规则按固定顺序判、先命中生效、有复合短路」，
但**参数全不同、判定方向逐条换过**。所以它测的是结构，不是答案。

> ⚠️ 两个 B 组的迁移机会都来自**贴着阈值的一次召回**（10.4 和 10.1，`min_abs = 10.0`）。
> 阈值再高 0.2 分，B 组就退化成 A 组。这个脆弱点必须和结论一起说。

## 5. 修正后的结论

原来的说法「净效果为零」，**只对通过率成立，对检查点不成立**。更准确的说法是：

> **skill 的迁移不是全有或全无。**
> 「多条规则按固定顺序判、存在一类一票否决、超长的走另一条路」——**这部分能迁移**，
> 让 B 组从 1.7/6 跳到 4.2/6，且高度稳定。
> 「阈值是多少、什么条件下免审」——**这部分迁移不过去**，B 组的边界题 0/6。
> 而判卷是「六条全对才算过」，所以 4.2/6 和 1.7/6 在通过率上是同一个数：**0**。

这个结论对主实验的解释更精确：**skill 的价值不是"给答案"，是"给判定骨架"**。
但有骨架不够——参数错一条，整题就废。这也解释了为什么主实验里必须"恰好有对应的那篇"：
只有那篇才同时给了骨架和参数。

### 顺带一个方法论收获

**判卷粒度决定了你能看见什么。** 只看通过率，A 和 B 完全一样（0/3 vs 0/3），
结论会是"skill 迁移毫无用处"；拆到检查点，才看见 1.7 → 4.2 的真实变化。
反过来说：主实验用二元通过率，**base 恒为 0 可能也掩盖了类似的部分得分**。
这一点值得单独查一次（见第 7 节）。

## 6. 与 2026-11-07 那次记录的差异（自我更正）

那次记的是「A 0/3（2/4/4），B 0/3（2/4/4）」，并据此写下「B 和 A 总分完全一样」。

今天重跑 t39：A 0/3（3/1/3），B 0/3（**5/4/4**）。

两种可能，我不排除第二种：

1. **代码变了**：11-07 之后修了沙箱拒绝文案（原来结尾是「用相对路径重试」，实测导致连续 19 次
   Bash 空转、烧到 167k token）。当时的运行可能被无效搜索吃掉了预算，推理质量被打折。
2. **11-07 那个数可能是手工数的、数错了**。两组各自三次都是「2/4/4」，
   这个完全相同的巧合本身就值得怀疑。

所以：**旧数字作废，以 `eval/run_heldout.py` 的输出为准。** 脚本逐条跑检查点、结果可复现，
这是它能取代手工记录的唯一理由。

## 7. 局限

- **n = 2 道题**。两个任务都支持同一结论，但仍是小样本，不能推"所有任务族都这样"。
- **B 组的迁移机会依赖贴阈值的召回**（10.1 / 10.4 vs 门槛 10.0）。阈值一变，B 组就退化成 A 组。
  这不是方法的问题，但会让结论的可复现性依赖一个脆弱的参数。
- **检查点是 6 条，权重相同**。一条结构判断和一条边界判断在分数上等价，
  但前者显然更"值钱"。用位图而不是加权分，是为了不引入我自己的主观权重。
- **未查**：主实验那 31 次 base 失败里，是不是也有"部分检查点通过"被二元判卷吃掉了？
  如果 base 平均能过 3/6，那"skill 把 0 变成 1"的故事仍然成立，但"base 完全不会"就不成立。
  **这个值得单独跑一次**（`--trace` + 位图统计）。
