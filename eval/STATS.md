## 二、主检验

### 配对 t 检验（n=9）

```
均值差 = 0.944    sd = 0.167
t = 17.00    df = 8    p = 1.46e-07
95% CI = [0.816, 1.073]
```

**这个 t 值不能按字面读。** base 侧全部是 0，配对差就等于 skill 侧通过率，
所以它**退化成了"单样本检验：skill 通过率是否显著大于 0"**——
描述的是"skill 侧离 0 有多远"，不是"两组差多少"。

另一个信号：**95% CI 上界 1.073 > 1.0**。通过率不可能大于 1，
说明数据贴到天花板了——这是饱和迹象，不是"效果特别大"。

### 符号检验（更该引用这个）

```
skill > base: 9 题        skill < base: 0 题        持平: 0 题
单尾 p = 0.0020
```

只问"方向对不对"，不依赖分布假设，也不被天花板效应放大。
**9 次配对全部同向，p = 2⁻⁹ ≈ 0.002** —— 这是这批数据里最硬的一条。

## 三、敏感性分析

| 处理 | n | 均值差 | t | p |
| --- | ---: | ---: | ---: | ---: |
| 全部（9 题） | 9 | 0.944 | 17.00 | 1.5e-07 |
| 剔除只有 1 个检查点区分的 t35/t36 | 7 | 0.929 | 13.00 | 1.3e-05 |
| 加回 t32（base 5/5 通过的反例） | 10 | 0.850 | 7.96 | 2.3e-05 |

- 剔除 t35/t36 后**结论不变、均值差略升** —— 这两题没有在"撑"结论，反而在拉低它。
- 加回两个反例，均值差从 0.944 掉到 0.803，**方向不变**。这是最坏情况下的下界。

## 四、必须承认的局限

### 1. base 恒为 0 是**设计出来的**，不是发现的

造题时就是按"base 会失败"筛的——`t32` 就是因为 base 5/5 通过而被排除。
所以这 9 题不是随机抽样，而是**筛选后的样本**。

> 换句话说：这个 p 值证明的是"**在我专门构造的这批题上**，skill 能救回来"，
> 不能推广成"skill 能提升一般任务 94 个百分点"。

### 2. skill 是为这些题写的（构造效度）

先造题、再补 skill，这是对的顺序；但"能补上 skill"本身成了入选条件之一。
一个盖不住的任务（校准题 t30）就被排除在统计之外了。

> 这是**机制有效性证明**，不是**效应量估计**。

### 3. 二元判卷会掩盖"部分得分"

按检查点重算（`eval/CHECKPOINTS.md`）：**剔掉作废的 t31 后**，base 过 **38/126 = 30%**，
skill 过 **125/126 = 99%**；base 27 次里只 1 次六条全对（t28，无泄漏，真猜对了）。
（未剔 t31 的原始结果是 53/144 与 143/144。）

> 所以准确的说法不是"base 完全不会"，而是**"base 会一部分、但过不了关"**；
> 而"31 次全败"只是小样本快照——主对照 31 次 + 复查 27 次合起来，base 58 次里通过 1 次（约 2%）。
> skill 补的是最后那几条它猜不到的参数。

### 4. 样本量刚好够，没有余量

n=9 略低于配对 t 的常规下限。符号检验在 9/9 同向时 p=0.002，已经接近这种设计的极限。

## 五、被移出主表的两个反例

| 任务 | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| t32 导出编码 | base **5/5** 全过 | 写了"业务方双击打开"，模型直接推出 BOM+CRLF——领域常识，不是内部约定 | 造完即标反例，从未进统计 |
| t31 重试预算 | base 原记 0/3，重跑 **2/3** | 六条规则（最多 3 次 / 退避 0.5,1.0 / 422 不重试 / 尊重 Retry-After / 超 60 秒放弃）**全是业界默认值**；原 0/3 是判卷 bug 的产物（当时只认 `sleep=time.sleep`，把参数化注入判成失败） | 2026-11-19 移出主表 |

**共同教训**：这两题都栽在同一道闸门上——"这条约定换个公司还成立吗？"
成立就不是内部约定，模型本来就会，测不出任何东西。

## 六、可以对外说 / 不能说

**可以说：**

> 在 9 个"答案不在仓库里"（需要公司内部约定）的任务上，
> 无 skill 时 31 次有交付的运行**全部失败**，有 skill 时 24/25 通过；
> **9 次配对全部同向，符号检验 p = 0.002**。

**不能说：**

- ❌ "通过率提升了 94 个百分点"（base 为 0 是筛选结果，且已贴天花板）
- ❌ "t = 17，效果极其显著"（t 被天花板效应放大，该引符号检验）
- ❌ "skill 让 agent 整体变强了"（只在这类任务上验证过）

**面试时更稳的说法：**

> 我做的不是"提升准确率"，是**给一个原本依赖模型先验知识的环节引入了可检索的外部知识**，
> 并且证明了在这类任务上它是**唯一能改变对错的机制**。
> 效应量我不敢给，因为样本是我筛的，天花板也已经顶到了。
> 而且后来我发现连"0"这个数字都有水分——按检查点算 base 能过 30%（剔 t31），
> 它不是"不会"，是"会一半、过不了关"；扩样本后 base 58 次里也真通过过 1 次。
