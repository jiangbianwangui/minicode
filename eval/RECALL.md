# 召回现状与失败模式（2026-11-12）

> 目的：在动手加"语义召回"之前，先量清楚**现在的召回到底错在哪**。
> 所有数字都能用仓库里的脚本复现，没有一次调用 LLM。

## 0. 先纠正一个说法

`skill_router` 不是"BM25 召回"，准确说是 **tag 字面准入 + BM25 微调**：

```python
specific = [t for t in tag_hits if t not in self.GENERIC_TAGS]
if not specific and not name_hit:
    continue                      # ← 硬闸门：BM25 再高也进不来
score = bonus + 0.2 * bm25        # ← BM25 只占 20% 权重
```

所以"同义改写召不回来"的根因不在排序，**在准入通道本身**。
这也决定了修法：语义通道必须**旁路这条 gate**，而不是把向量塞进 BM25 那一项。

## 3. 拆因：是阈值太严，还是通道不通？

`python eval/threshold_sweep.py`

| min_abs | 原始集 正确首位 | 原始集 误召 | 改写集 首位正确 |
| ---: | ---: | ---: | ---: |
| **10.0（当前）** | **12/12** | **0/32** | **0/22** |
| 8.0 | 12/12 | 0/32 | 0/22 |
| 6.0 | 12/12 | 0/32 | 1/22 |
| 5.0 | 12/12 | 1/32 | 1/22 |
| 4.0 | 12/12 | 2/32 | 2/22 |
| 3.0 | 12/12 | 6/32 | 4/22 |
| 2.0 | 12/12 | 13/32 | 10/22 |
| 1.0（≈不设阈值） | 12/12 | 13/32 | 10/22 |

三件事同时被这张表证明：

1. **阈值不是原始集的问题**：从 10 降到 1，原始集始终 12/12 —— 那些查询的分数远高于 10。
2. **降阈值救不回改写集**：即使完全不设阈值，也只有 10/22。剩下 **12 条是 tag 闸门根本没过**（语义相同、词面零重叠，如"200 毫秒内返回"对 tags `sla/超时/预算/timeout/deadline/降级/重试/网关`）。
3. **降阈值的代价极高**：3.0 时误召 6/32，2.0 时 13/32。用 13 条假阳性换 10 条真召回，不划算——假阳性会把 agent 引到一篇不相关的规范上，比不召回更糟。

> ⚠️ 一个必须承认的混杂：改写查询通常只有一句话，原始查询是多句规格，
> **查询长度天然影响 tag 命中数**。所以第 2 点不能简单说成"语义不匹配"，
> 它同时包含"短查询拿不到足够 tag 命中"。两者都指向同一个修法（换通道，不换阈值）。

## 4. 结论

- **12/22 的失败是结构性的**：tag 字面准入 → 同义改写进不来 → 调参无解。
- **10/22 可以靠放松阈值拿到**，但代价 13/32 误召 → 不值得。
- 所以下一步不是"调参"，而是**加一条旁路的语义通道**（embedding top-k → 与原通道 RRF 融合），
  并且必须做到"原始集 12/12、误召 0/32 不退化"才算成功。
- 验收标准先定好：**改写集 recall@1 提升，且原始集 12/12 + 0 误召不变**。
  只报前者不报后者 = 允许用误召换召回。
