# heldout/ — 留出任务的参考 skill

这个目录里的 skill **不参与路由加载**（router 只扫 `skills/`），
用途是验证某个留出任务的"可解性上限"。

## 为什么需要它

如果一篇 skill 留在 `skills/` 里，这个任务就变成"开卷"——
base 也能召回到答案（t38 就因此被击穿一次）。
留出任务的价值在于：**它永远没有对应 skill**，可以用来测"现有库能不能迁移过去"。

但判卷要证明"这题确实可解"，所以参考 skill 得留着 —— 放在这里，
需要跑 C 组（上限验证）时手动复制进 `skills/`，跑完移回来。

## t39 三组对照的结论（2026-11-07）

| 组 | 给什么 | 通过 | 检查点 |
| --- | --- | ---: | --- |
| A | 什么都不给 | 0/3 | 2 / 4 / 4 |
| B | 现有 13 篇库 | 0/3 | 2 / 4 / 4 |
| C | `t39_reference_skill.md` | **3/3** | 6 / 6 / 6 |

关键发现：**B 和 A 的总分完全一样**，但内部结构变了 ——

| 检查点 | A | B |
| --- | --- | --- |
| 单规则短时直通 | FAIL | **PASS** |
| 31 分钟不再豁免 | PASS | **FAIL** |
| 其余四条 | 3 PASS / 1 FAIL | 3 PASS / 1 FAIL |

B 组读了 `backfill-approval-policy` 后，**把"直通"从最后一条挪到了第 0 步**
（A 组把它写在函数末尾，等于没有）—— 这是结构知识的迁移。
但参数全是猜的（短时阈值 60 而非 30、长时阈值 240 而非 1440），
换掉的那一条正好抵消了收益。

> **结论：skill 能迁移"结构"，不能迁移"参数"。**
> 净效果为零 —— 这也解释了为什么在此之前所有有效题都要求 skill 与任务严格对应。
