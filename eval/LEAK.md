# 泄漏审计：base 组真的"没有 skill"吗

## 1. 结论先说

**不是保证，只是设计。**

沙箱是靠**正则匹配命令字符串**实现的（`tools.py::_ESCAPE_PATTERNS`）。只要 Bash 能跑 Python，
就有无穷多种绕过写法：`chr(47)` 拼路径、`os.path.join` 拆段、`\x43:/Users` —— 正则永远追不完。
真正的隔离要靠容器，README 里一直这么写，但没做。

所以「base 没有 skill」这句话的正确含义是：**路由没给它**，而不是**它拿不到**。

## 2. 触发这次审计的那个观察

2026-11-19 用 `eval/checkpoint_profile.py` 按检查点剖析 base 的十个任务，t34（灰度门禁）**6/6 全过**。
和主结论「base 31 次有交付全败」直接冲突，所以去看产物：

```
DEGRADATION_THRESHOLD_PP = 0.8
MIN_SAMPLES = 500
BURN_RATE_ROLLBACK = 3.5
HOLD_STREAK_TO_ROLLBACK = 2
```

**这四个数一个不差，全是 `skills/canary-gate-policy/SKILL.md` 里的值**，连解释文字都高度相似。

同一条命令序列当天复跑一次（带 `--trace`）：它只写了 `0.1 / 1000 / 2.0 / 5.0`（自己的猜测），失败。

所以这不是"模型本来就知道"，是**那一次它读到了文件**。怎么读到的没查出来——
所有我能想到的路径（绝对路径 ReadFile、`../../skills`、`cd ..`、Grep、Glob）都试过，全部被拦。
这恰恰印证第 1 节：**正则拦得住我想到的写法，拦不住我没想到的。**

## 3. 于是换判据：不看命令，看产物

`eval/leak_audit.py`：拿产物和每篇 skill 正文比**连续逐字重合**的长度（归一化去空白标点后）。
不问"它怎么读到的"，只问"结果里有没有 skill 原文"。

阈值是实测校准出来的，不是拍的。校准过程中撞出三类误报：

| 误报 | 长度 | 真相 |
| --- | ---: | --- |
| `with pytest.raises(ValueError):` | 24 | 样板代码，9 个无关任务都有 |
| `orderid amount pay_channel page_id …` | 32 | 任务自带 `schema.py` 里就有这串字段 |
| `窗口从上一次被接受的上报开始算…不刷新窗口` | 31（+9 字续写=40） | **t35 的脚手架 docstring 本来就写了这句**，产物只是自然续写了半句 |

前两类靠抬高阈值处理；第三类必须**先把产物的脚手架部分挖掉再比**（`_mask()`），
否则整族 t35 会被误判成泄漏。修完之后再扫，t35 全部清零。

最终判据：**≥ 40 字连续重合判泄漏；32–39 只提示不计入。**

## 4. 全量扫描结果（2026-11-19）

```
扫描 1071 个 workspace，9 个有 ≥40 字逐字重合
其中 8 个是 skill 组（本来就该有 skill 原文）
**剩下 1 个是 base 组：t34_cp_base1**
```

非 skill 组共 **993** 个 workspace，泄漏 **1** 个（约 0.1%）。

必须说清这个数字的局限：workspace 会被重跑覆盖，**993 是"留下来的"不是"跑过的"**，
所以它既不是泄漏率的准确估计，也只能当量级参考。

## 5. 对已有结论的影响

| 结论 | 影响 |
| --- | --- |
| base 0/31、skill 27/28、p=0.001 | **方向不受影响**。泄漏只会让 base 更容易通过，所以真实差距只可能更大，不会更小 |
| 「base 完全做不到」 | **要降级为「base 大多做不到」**。至少有一次它绕过沙箱把参数拿到手了 |
| 「base 有时也能过」 | **不成立**。t34 那次 6/6 是泄漏得来的，不是能力 |
| 十任务检查点剖析（17/48） | 扣掉 t34 → **11/42（26%），通过 0/9** |

## 6. 怎么用

```bash
python eval/leak_audit.py --workspace eval/workspaces/t34_cp_base1   # 单个
python eval/leak_audit.py --all                                      # 全部
```

做任何"base vs skill"的对照之前，**先对 base 组的产物跑一遍这个**。
它不能阻止泄漏，但能把"我以为是能力，其实是它偷看了"这类错误当场暴露出来。

## 7. 没解决的问题

1. **泄漏路径未知**。我知道结论（它读到了），不知道手法。想知道只能靠文件访问审计
   （Windows 上要 Procmon 之类），成本高于收益。
2. **根治只能靠容器**：把 agent 跑在没有 `skills/` 的镜像里，读取就无从谈起。
   这是 `README` 里一直挂着的已知限制。
3. **993 这个分母不可靠**（见第 4 节）。
